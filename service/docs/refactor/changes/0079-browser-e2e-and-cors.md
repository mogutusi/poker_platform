# 0079 · 真实浏览器端到端:抓出 CORS、空大厅死路、ws 竞态

日期:2026-08-17 · 性质:**前端建设 + 一处后端补齐**(CORS)· 触发:承接 [0078](0078-frontend-table-wiring.md) 的待办第 1 条「界面还没人真正点过」。

## 结论一句话

用 Playwright 开真 Chromium 走了一遍用户旅程,**一次抓出三个此前所有测试都盖不到的问题**:后端没配 CORS(浏览器根本发不出登录请求)、空大厅没有任何入口能进房间(动态建房模型下就是死路)、ws 连接在组件卸载时的一处竞态。四个浏览器用例现已全绿。

## 为什么必须有这一层

到 0078 为止有两层验证,但都盖不到浏览器:

| 层 | 验什么 | 盖不到什么 |
|---|---|---|
| vitest 50 项 | 状态归并、seq 纪律、加密向量 | 页面是否真能用 |
| `npm run smoke` | 协议层跑通一手牌 | **Node 里没有 CORS、没有 DOM、没有 React 生命周期** |

这三个问题全都落在「盖不到」那一栏里。

## 抓到的三个问题

### A · 后端没配 CORS,浏览器连登录都发不出去(后端改动)

浏览器控制台:

```
Access to fetch at 'http://localhost:8000/user/login' from origin 'http://127.0.0.1:3000'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present
```

前端在 3000、后端在 8000,是**不同的源**,浏览器会先发预检;服务器不回 CORS 头,整个请求就被拦掉。Node 里的 fetch 不受同源策略约束,所以协议层冒烟一路绿灯也发现不了。

**动手前先按纪律查过**:CORS 在 docs 和代码里**从未出现过**——不是有意的决策,而是后端从来没被浏览器访问过(只有 pytest 和 Node 冒烟)。所以这是补空缺,不是推翻既有设计(0074·B 的教训:「A/B/C 都做了唯独 D 没做」时先假设 D 是有意的;这里是「谁都没做过」)。

做法:

- 来源白名单进 `app/config.py`(基础设施轨,不是 gameconfig 的游戏参数轨),默认放行本机前端的两种写法——**`localhost` 与 `127.0.0.1` 是不同的源,必须都列**,只列一个换种写法就连不上。
- `create_app()` 里按配置装 `CORSMiddleware`;配置留空则不装,对应同源部署(反代到同一域名)时根本不需要 CORS。
- **不用 `*`**:带凭据时通配无效,也不该放任任意来源。方法只放 `GET`/`POST`,即前端实际用到的。
- 补 `tests/rest/test_cors.py` 三项钉住:装了中间件、来源是明确列举且含两种本机写法、方法集合精确。

### B · 空大厅是死路

房间是**动态创建**的(0049),所以初始一个房间都没有。但大厅的座位是从 `rooms[0]` 派生的——没有房间时 `room` 为 null,点任何座位都直接 return,**用户没有任何办法开一桌**。

单测发现不了(它不渲染),协议冒烟也发现不了(它直接发 `join_room`,绕过了界面)。

修法:大厅加一个房名输入 + 「进入房间」按钮。进一个不存在的房名,后端就地建房。同时把标题与人数改成显示真实房间数据(`room.id`、`seated / max_seats`),没房间时显示「暂无房间」而不是写死的「9 Players」。

### C · ws 连接在组件卸载时的竞态

页面抛出未捕获错误 `ws not connected`。

机理:`enterRoom` 要先 `await` 一次 REST 取昵称,组件可能在这期间就卸载了——**React 严格模式下开发期 effect 会跑两遍(挂载 → 卸载 → 再挂载),必然撞上**。卸载会 `disconnect()`,但先前注册的 `onStateChange` 回调仍挂在 ws 单例上,连上时照样触发一次 `send`,而 socket 已经没了。

修法两处:

- `disconnect()` 连同 `handlers` 一起清掉——组件走了之后,尚未触发的回调不该再回调到它。
- `enterRoom` 加一个 `isCancelled` 参数,`await` 回来先检查;牌桌页的 effect 清理时置位。

这个 bug 在生产构建下可能很少见(严格模式的双跑是开发期行为),但根因是真的:异步启动 + 单例连接 + 可随时卸载的组件。

## 浏览器用例(`npm run test:e2e`)

```
✓ 登录页在没有 K_user 时要求填写
✓ 密码错误时给出提示,且不跳转
✓ 登录 → 大厅 → 牌桌:观战、入座、买入
✓ 未登录直接开牌桌页会被送回登录页
```

几个写法上的取舍:

- **按 `button[type="submit"]` 定位,不按文案**。按钮上的字是设计的一部分,改字不该弄坏测试(第一次就是按文案写的,而按钮实际叫 "Enter",直接失败)。
- **站内跳转,不用 `page.goto`**。`session_token` 只在内存,整页加载就丢——这是 [transport.md](../../../../frontend/docs/transport.md) §六 的有意取舍,另有一条用例专门验「未登录直接开牌桌页会被送回登录页」。
- **每个用例用不同的 dev 账号**。一开始四个用例都用 alice,单跑全过、全套跑就挂——同账号在用例间会互相顶替连接,也可能把上一轮的房间残留带过来。这一条排查花的时间最多,教训是:**共享后端状态的测试之间,账号必须隔离**。
