# 0096 · 离房即弃免盲:`_evict` 清掉 `waive_entry_for` 的残留(BUG-13)

日期:2026-08-25 · 性质:**缺陷修复(core reduce)**· 触发:[BUGS.md](../BUGS.md) BUG-13(0072·N-e16),low 组里唯一真的影响筹码的一条。

## 缺陷是什么

免盲投票通过后,受免者的 nick 进 `room.waive_entry_for` 快照,等 `_start_hand` 消费(免掉入局 post)。但 `_evict`(离房驱逐的唯一出口:主动 `LeaveRoom`、占座到期 `Cleanup`、手尾驱逐)只清座位、成员表和 `work.users`,**不清这份快照**。于是:

- **退房再进白拿免盲**:投票通过 → 受免者 `LeaveRoom` → 重新 `JoinRoom`+`SitDown` → 下一手开局时 nick 还在快照里,免掉本该付的入局 BB。这与 rules.md 测试 ①.9「退房再进躲盲被堵」直接冲突——①.9 守的就是「离房重进不能逃盲」,而这条路径恰好用投票残留绕开了它。
- **残留 nick 会转给别人**:改名只在大厅发生,受免者离房后就能改名腾出旧 nick;别的账号改成这个 nick 再进房入座,凭一份并非投给他的快照免盲入局。

## 为什么断定是缺陷、不是有意设计(本仓纪律:先读设计文档)

[rules.md](../../rules.md) ①「免盲投票」的既有语义**处处把「离场」当作弃权**,唯独这一处漏了:

| 时点 | 离场的后果 | 出处 |
|---|---|---|
| 投票进行中,候选离场 | `waived = 冻结候选 ∩ 当前 new_here`,离场者没有座位 → 剔除;全离场则「票失对象、失败」 | `_finish_entry_vote`、rules.md ①「候选冻结」 |
| 投票进行中,投票人离场 | 投票人集合实时重算(①.15) | `_maybe_resolve_entry_vote` |
| **投票已通过,受免者离场** | **什么都不发生,快照带着他的 nick 一直活到下一次开局** | ——(本缺陷) |

同一个人、同一张票,离场时刻差一秒,结局从「失对象」变成「终身有效」——这不是设计,是 `_evict` 漏了一处清理。0020 落地投票簇时 `_evict` 早已存在(0014),两边没有对上。

窗口虽窄(快照只活在「通过 → 下一次 `_start_hand`」之间,开局即整体清空),但它免的是真金白银的入局 BB,且是 low 组唯一影响筹码的一条。

## 打算怎么改

`_evict` 里加一行:`room.waive_entry_for.discard(nick)`。

- **改在 `_evict` 而不是 `_leave_room`**:`_evict` 是所有离房路径(LeaveRoom 即时 / Cleanup 到期 / 手尾驱逐)的唯一汇聚点,改这里三条路一起覆盖;改在上游任何一处都会漏掉别的路径。
- **手尾驱逐路径顺带被罩住**:投票人 = `READY_TO_PLAY` 座位,手内玩家是 `PLAYING`,所以票可以在手中由局外人投通过、快照在手中写入;手尾 `_finalize_hand` → `_evict` 的离场者若在其中,同样是残留。`discard` 对不在集合里的 nick 是 no-op,统一清不需要分支。
- **起身(→WATCHING)不清,有意不动**:起身走 `_release_seat`,人还在房里。免盲是全票让利给「这个人」,他没离房、nick 也不可能被别人占(改名仅限大厅),重新坐回消费这份让利与投票人的意图不冲突;0023 也记过「免盲只写 waive_entry_for,他仍须 READY 被发牌才消费」的无害论证。只有**离房**是不可逆退出(与 ①.15 投票人离场触发重算同一口径),才没收。

## 实际改了什么

按计划落地,一处**对「打算」的更正**(见下)。

- **`core/reduce.py`**:`_evict` 在移出成员表之前 `room.waive_entry_for.discard(nick)`,注释写清三件事:为什么要清(①.9 会被残留绕开 + 改名接盘)、与哪条既有口径同向(候选离场失对象)、为什么起身不清(人未离房)。
- **`tests/core/test_free_entry_vote.py`** 三条回归:
  - `test_leaver_forfeits_waiver_and_pays_on_reentry`:通过 → D 离房 → 快照剔除 → D 重进/重坐/买入/准备 → 开局断言 **`bet_amount == BB and points == 100 - BB`**——断言钉在筹码面(入局 post 真的收了),不只钉集合内容;残留免盲下这两个值是 `0/100`。
  - `test_cleanup_eviction_forfeits_waiver`:在座者掉线(可逆)快照不动 → `Cleanup` 驱逐才剔除。顺带把「在座者掉线不弃权」钉住,与 ①.15「不为断线单独触发通过」同一设计。
  - `test_eviction_forfeits_only_the_leavers_waiver`(**自 review 补**):同一票免掉 D、E 两人,E 离房后断言 `waive == {"D"}` 且 D 下一手仍免费入局。见下「自 review」维度 ⑥——没有这条,把 `discard` 写成 `= set()` 全绿。

### 对「打算」的更正(两处,第二处比打算里写的更强)

1. **手尾驱逐那条不是活路径,而且理由比我写的更强。** 打算里说「票可在手中通过、离场者若在其中同样是残留」——**推导错了**,而且错了两层:
   - 手尾 `_evict` 的对象是 `room.leaving`,只有**本手参与者**进得去(非参与者在 `_begin_leave` 就即时驱逐);而参与者发牌即清 `new_here`,不可能在只快照 `new_here` 座位的 waive 集里。
   - 更根本的是(自 review 抓出):**手中根本不可能有票通过**。`_start_hand` 同时清空 `waive_entry_for` 与 `entry_vote`([reduce.py](../../../app/core/reduce.py) `_start_hand` 末段);手中被发牌者是 `PLAYING`、未发牌在座者一律被重标 `new_here=True`,而投票人须「非 `new_here` 且 `READY_TO_PLAY`」⇒ 手中 `_voters` 恒空;开票与通过都要求 `voters` 非空 ⇒ 手中既开不了票也过不了票。**所以 `waive_entry_for` 在整手期间恒为空集**,手尾那条路上的 `discard` 是纯防御性 no-op。
   - 修法不因此改变:`_evict` 仍是唯一正确落点,各路统一清、不需要分支。
2. **离房的入口比打算里列的多一个:观战者掉线。** `_disconnect` 对 `WATCHING` 者不标 OFFLINE,而是即时 `_begin_leave` → `_evict`(0070 定的观战者断线即离场)。于是「起身(→WATCHING)保留免盲」+「观战者掉线即离场」组合起来,**起身后再掉线的人会弃权**。实测复放确认过。这与设计一致(他此刻真的离开了房间),但 rules.md 初稿那句「掉线**不**弃权」是**过宽断言**,已改成「在座者掉线不弃权 / 观战者掉线即离场故随离房弃权」三条,BUGS.md 的摘要同步改准。

## 自 review

按 [review.md](../../review.md) 七维。本批动的是 **core reduce 的离场路径**,最高风险面是「清多了」(误伤别人的免盲)与「清漏了」(还有别的离房入口)。方法上用了并行多 agent 对抗式复审(四组维度 → 每条发现两个独立视角试图证伪),**抓到 3 条,其中 2 条实质、我逐条实跑复核过**,不是只读报告就采信。

- **① 分层 / 不变量**:core 仍纯同步——新增的是一次集合 `discard`,无 `await`/IO/墙钟。**工作副本纪律逐条核过**:`_evict` 拿到的 `room` 是 `checkout` 深拷出来的工作副本(`work.room`),命令失败整份丢弃,`world` 一字节不动。**不变量 7(事件不持有会被改写的引用)**:`waive_entry_for` 从不进任何事件——`FreeEntryVoteClosed.waived` 是通过那一刻算出的 `tuple` 值快照,`StateSnapshot` 根本不投影这个字段,所以 discard 改不到任何已产出事件的内容。筹码守恒不受影响(discard 不碰 points),但**它决定下一手要不要收入局 BB**,所以断言必须落到筹码面(见 ⑥)。
- **② 代码↔文档同步**:[rules.md](../../rules.md) ①「免盲投票」补「离房即弃权」三条。**初稿在这里写错过一句**:「掉线**不**弃权:可逆、保座」是过宽断言——起身(→WATCHING)的人保留免盲(有意),而观战者掉线走的是 0070 的「即时离场」分支,于是他确实会弃权。实测复放确认后改成三条(在座者掉线不弃权 / 起身不弃权 / 观战者掉线即离场故随离房弃权),并把 `_evict` 的入口枚举补上「观战者掉线」。协议面零改动:`waive_entry_for` 从不上 wire,故 codegen 与 [BACKEND_GUIDE.md](../../../../frontend/BACKEND_GUIDE.md) 不动(核实过,不是推测)。
- **③ 文档↔文档一致**:[BUGS.md](../BUGS.md) 划掉 BUG-13(不删行)+ 进「已修复」表,摘要与 rules.md 的三条口径一致;[TODO.md](../TODO.md) 的 N-e16 镜像条目**同批划掉**——0093 的教训就是只清一处等于制造新漂移。本批改动文档的相对链接全扫过,0 死链。
- **④ 数据模型正确性**:`waive_entry_for` 是 `set[str]`,`discard` 对不在集合里的 nick 是 no-op,所以三条离房路径不需要分支判断,也不会因「他本来就没被免」而抛 `KeyError`(这正是不用 `remove` 的理由)。集合是**多人 union**(`|= waived`),这一点直接决定了修法必须是定向 `discard` 而不是整份重置——见 ⑥。
- **⑤ 规范合规**:注释中文、讲「为什么」(为什么要清 / 与哪条既有口径同向 / 为什么起身不清),不复述代码;无魔法数、无死代码、无调试输出;测试注释与文件既有 idiom 一致(每条前面一行 `── 说明 ──`)。`git status` 复核过工作树只有预期的 6 个文件,无 `.bak`、无变异残留(两轮变异都用 `sed` 反向替换还原并 `grep` 确认)。
- **⑥ 测试充分**:**这一维抓到了本批最实质的缺口**。原来两条回归都只有 D 一人被免,断言 `waive_entry_for == set()` 对「定向剔除」和「整份清空」两种实现**都成立**——把 `discard(nick)` 写成 `= set()`,762 个测试全绿。而多人 waive 集是真实可达的(同一票可免多人,`test_multi_candidate_waive_sorted` 就以 `{"C","D"}` 收尾),那种实现会在任意一次离场时静默毁掉别人已获全票通过的免盲,让他下一手白付一个入局 BB。已补 `test_eviction_forfeits_only_the_leavers_waiver`(免 D、E 两人 → E 离房 → 断言 `{"D"}` 存活 **且 D 下一手真的免费入局**),该变异现在必红。**缺口如实记**:(a) 没有端到端(浏览器/冒烟)用例覆盖「免盲通过 → 离房 → 重进」这条路径,现有 e2e 的免盲用例走到「新人真的免盲入局」为止;(b) 「起身后掉线弃权」这条组合路径由实测复放确认、但没有留成常驻用例——它是既有两条设计(起身保留 / 观战者掉线即离场)的组合结果,不是本批新增行为,故记档而非补测。
- **⑦ 流程账本**:本篇即账本。变更记录先行(写完「打算」才动代码),收工回填,**两处「打算 ↔ 实际」的偏离都明写并论证**:手尾驱逐那条不是活路径(而且理由比打算里写的更强——手中 `waive_entry_for` 恒为空,论证链逐条指到行),以及离房入口漏了观战者掉线。提交信息用英文、引用 0096。
