## 一、大厅:摘要 + 入口

用户定的规则:**大厅里每个模块只给摘要,详情页承载全量和操作。** 落到四处:

1. **椭圆牌桌 = 当前房间**,按用户的话「大多数时间就一个房间」。但做成灵活的:
   - 不写死索引;房间数 > 1 时给 `‹ 1/3 ›` 箭头 + 下拉,**不把别的房间藏起来**;
   - 一个房间都没有时**桌子照常显示为空桌**,配「开一桌」入口,不隐藏;
   - 座位仍是匿名占位——大厅拿不到「谁坐哪」(那要进房后由 `StateSnapshot` 给),**不编造玩家名**。
2. **排行榜**只显示前 5 + 「查看完整排行」入口,并**标注「不含桌上筹码」**。后端排的是结算后的全局积分,一个人把积分全买进牌桌后在榜上会显得很低,不标注看起来完全像 bug(见 [rest.md](../../rest.md)「坑 · 排的是结算后的全局积分」)。
3. **最近手牌**摘要 + 入口指向 `/history`。
4. **头像卡片可点** → `/settings`。账号设置只留这一个入口,不另加导航项。

> 「查看完整排行」目前标注为「待建」且不可点——**没有造一个指向不存在路由的假链接**。排行榜详情页留作后续。

## 二、`/settings` 账号设置

四块:我的资料、改昵称、改密码、**更换 K_user 密钥**。

最后一块是本页存在的关键理由:管理员每周轮换密钥,轮换后用户必须换本地这把,**否则下次登录直接登不进来**。此前唯一入口是登录页上一个小链接,已登录的用户看到 `rotate=true` 提示后根本没地方去换。现在这页常驻显示「你在用旧钥匙」。

错误分层做了细分,因为**同一个状态码在两个端点含义完全不同**:改昵称的 403 是「人还在房里」,改密码的 403 是「旧密码错」,共用一句文案会误导人。409 单独给「昵称被占」。另外后端把「空 / 首尾带空白 / 超 50 字 / 与现名相同」全归成一个 400,回包分不出是哪种,所以提交前在本地先拆开各给准话。

## 三、`/history` 手牌历史

后端 `GET /hands` 早就做好了(0051/0052),前端此前引用 **0 次**——纯粹浪费掉的功能。

- 默认看自己的,游标翻页(`before=` 列表最后一条的 id),不用页码。
- 每手显示时间、房间、底池、**自己的盈亏**(正负配色)、同桌都有谁。
- 三态齐全:加载中 / 失败 / 空态,都不是白屏。
- 房名从 `dedupe_key` 还原:后端 `HandRecordView` **不带独立的 room 字段**,而且房名是用户可起的动态名、自己可能含冒号,所以按**最后一个**冒号切,不能 `split(':')[0]`。

## 四、私聊抽屉

用户点名担心「和房间聊天弄混」,以及「抽屉会不会太大」。处理:

| | 房间聊天 | 私聊 |
|---|---|---|
| 位置 | 牌桌页面内 | **右侧全局抽屉**,大厅和牌桌同一位置同一样式 |
| 持久性 | 只在内存留最近 N 条,随房销毁 | 落库,离线也收得到 |
| 未读 | 没有这个概念 | **有未读徽标** |

未读徽标只给私聊——房间聊天不落库、不在场就是错过,本来就没有「未读」可言,给了反而是撒谎。收起态只是一个带未读数的小浮标,展开不超过屏幕 1/3 且可关。

几个协议语义上的坑,都按后端文档核过:

- **发件人成功路径零回包**([messaging.md](../../messaging.md)),所以本地乐观追加,送达确认只能靠 `dm_read` 回执。
- **`read_through` 是时间游标不是 id**,服务器按 `created_at > 游标` 算未读,所以 `markRead` 只取**对方消息的 `created_at`**,绝不拿本机 `Date.now()` 顶;回执游标做「只进不退」,防登录补收的旧回执把进度带回去。
- **登录补收会重发离线期的消息**,所以按 `msg_id` 去重必须幂等。
- **`dm_undelivered` 只带 `to_nick` 不带 `msg_id`**,所以标「最近一条尚未标失败的自己发的消息」;对端不存在是稳定事实,连发 N 条会收到 N 次回执,依次往前标不会错位。

## 五、牌桌页只保留「离开牌桌」一个出口

用户已定案。原因是牌桌页卸载即断 ws,后端按在座断线处理(标 OFFLINE、保留座位、筹码锁在桌上等清理到期)。如果在牌桌上放「历史」链接,用户点一下就悄悄离桌了,而他以为只是去看了眼战绩。

已核实牌桌页只有「离开牌桌」和会话失效两条跳转,没有混进设置/历史链接。

## 六、测试

浏览器用例 6 → 10,新增 `e2e/hub.spec.ts` 四条:排行榜标注、头像卡进设置、历史页可开、私聊抽屉可开可关。

**大厅改造把原有三个用例弄坏了**——它们写死找「进入房间」按钮,而新大厅在空房时文案变成「开一桌」。这正是测试该起的作用。修法是**给按钮补 `data-testid`,让测试按钩子定位而不是按文案**:文案本来就该随状态变,不该因此弄坏测试。私聊抽屉则直接用 `aria-label` 定位——无障碍标签比 testid 更好,它同时是给读屏用户的说明。

## 七、续做:结算结果与连接状态上界面(原 0081·A)

这两条的数据 store 里一直有,只是没接到界面,而用户感知比新功能强得多。

**`HandResult`**:`hand_ended` 一到就弹出面板。先说和你有关的那句(「你赢了 N」或「这手没有赢到底池」),再列全表。**赢取与退还分开显示**——退还是「没人跟的注原样还给你」,不是赢来的钱,混在一起会让人以为赢得更多。新一手开始时 `hand_started` 自动清掉,也可以手动关。

**`ConnectionBanner`**:只在不正常时出现,连上了完全不占地方。断线时明确说「你的座位和筹码会保留一段时间」——这正是后端的实际行为(在座断线保留座位到清理到期),不说的话用户会以为筹码没了而慌。`closed` 单独一档,提示可能是会话过期或账号在别处登录。大厅和牌桌共用同一个组件。

补了 4 条单测,其中一条钉住**新一手开始要清掉上一手的结算**(否则面板会挂在新牌局上);浏览器用例里也加了断言,确认面板真的弹出、内容正确、能关掉。78 单测 + 10 浏览器用例全绿。
