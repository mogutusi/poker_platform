# 0093 · 账本对齐:同一件事登记在两处,只清了一处

日期:2026-08-25 · 性质:**流程账本修正(纯文档)**· 触发:用户问「现在还有什么要做的」时按 [TODO.md](../TODO.md) 逐条核对,发现它与 [BUGS.md](../BUGS.md) 已经对不上。

## 问题

0072 那一轮排查的产物**同时登记在两处**:

- [BUGS.md](../BUGS.md) —— 缺陷册(按严重度组织,0076 建立);
- [TODO.md](../TODO.md) 的「0072 架构审计」一节 —— 当时的任务清单条目。

0088 / 0090 / 0091 / 0092 修掉了其中五项,收工时都按规矩去 BUGS.md 划了掉,**却没动 TODO.md 里的镜像条目**。于是 TODO 上仍挂着五条早已修完的「待办」:

| TODO 条目 | 实际 |
|---|---|
| 0072·R2(Timeout staleness 跨手) | 0090 已修 |
| 0072·N9(StateSnapshot 不投影 entry_vote) | 0088 已修 |
| 0072·N-e32(离场者收不到结算) | 0091 已修 |
| 0072·C3(`big_blind=2*`) | 0092 已修 |
| 0072·D2(不变量 2 缺豁免判据) | 0092 已修 |

后果不是「少做了什么」,而是**账本会骗人**:下一个人照 TODO 挑活,会去修四条已经修好的东西;反过来,如果他信了 TODO 而不信 BUGS,又会以为 BUGS 的「已修」是假的。README §5 把变更记录称作「代码、文档、计划三者对齐」的账本——账本自相矛盾,比缺一条记录更糟。

## 改了什么

1. **TODO.md 的五条镜像条目就地对齐**:勾掉并写清修于哪一批。不只写「已修」,还把**登记当时说错的地方**一并写上——这几条恰好都有:
   - R2 登记写「补 `hand.seq` 双键」,而双键**不够**(seq 只在房内单调,目标房又是按「他现在在哪」解析的),实际落地是三元身份;
   - N9 登记只说「快照加投影」,而那只是一半(重连恢复成 SITTING_IN,人回来并不是合格投票人,再点 Ready 才是,而这件事此前无事件承载);
   - N-e32 登记的第二条备选「调整驱逐与广播顺序」**走不通**(dispatch 对整批事件用同一份 commit 后成员表)。
2. **D2-D5 那条从 `[ ]` 改 `[~]`**,列出已完成的 D1/D2 与余下的 D3/D4/D5。
3. **0088/0090/0091/0092 各补一段「收工后补记」**,指回本篇。历史记录不改写,但要留痕:那四篇的「自 review ⑦ 流程账本」当时都声称账本已对齐,而事实上只对齐了一半——不留痕就等于让四篇错误的自我声明留在册子里。

## 为什么会漏

`BUGS.md` 是 0076 之后的**唯一**缺陷清单,所以修完只想着去那里划掉;而 TODO 里那一节是 0072 当轮留下的、**同一批缺陷的另一份登记**,它在文件中段、不在「本批相关」的视野里。

**这不是「下次仔细点」能解决的**,而是登记本身有两份。真正的修法是让 0072 那一节只留指针、不留内容(缺陷正文一律以 BUGS.md 为准),已在 TODO 该节顶部加了一句口径说明——但**没有**把那一整节现在就压缩掉:其中还有若干条(N5 会话吊销、N-低危六条)尚未进 BUGS.md 或仍是待办,现在压缩会丢信息。这一条留档为后续动作。
