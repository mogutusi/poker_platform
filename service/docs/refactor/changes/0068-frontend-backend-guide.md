## 背景 / 为什么

前端接入的资料此前散在 service/docs(协议指南/auth/architecture)且视角是后端的;前端开发者需要一份**以前端为读者**的入口文档:后端心智模型(服务器权威/命令进消息出/快照对齐,推导出「前端不写牌局逻辑、不需要乐观更新、不需要事件回放」)、两条通道分工、**国密加密层的实现级事实**(前端要自己写 TS 实现,互通细节最易烧时间)、联调路径(明文 dev 通道先行)、常见坑。定位是「理解 + 契约」,不规定前端代码组织(用户明示)。

## 关键点

- **国密节实现级精确,全部对码核实**:SM4-CBC = PKCS#7(整块再补一块,`ttxsgm/sm4.py:311`)、HMAC-SM3 = 标准构造(块 64B/ipad 0x36/opad 0x5C,`channel.py:27`)、`KDF_sm3(x,n)=SM3(x)[:n]`(`sm3.py:75`)、ws/REST 密钥分域 0x01-0x04、帧形 `iv‖ct‖mac` + `seq(8B,BE)` 入 ct、**seq 首帧=1**(`channel.py:131` seal 先自增)、跨重连续 seq、REST seq 回显/重试=新 seq。指路 `tests/crypto/` 抄已知答案测试。
- **心智模型四句话**(服务器权威/串行命令/失败私发 error/快照对齐)+ 各自对前端的推论,替代照抄 architecture.md。
- 数字类事实取自 `poker.env.example` 基线并措辞为「默认」(90 秒保座、约 2 分钟登录新鲜窗),不硬编码进契约。
- dev 明文通道放显眼位置:UI 全流程可零加密先行,加密层最后接。
