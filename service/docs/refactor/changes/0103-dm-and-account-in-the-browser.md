## 打算怎么改

新建 `e2e/dm-and-account.spec.ts`,三条:

1. **两人真收发**:两个浏览器上下文(`eve` / `frank`),都停在大厅(**不进房**),eve 开抽屉 → 输昵称开会话 → 发一条;断言 frank 那边**真的收到了文本**、未读徽标出现;frank 打开会话读掉 → 断言 eve 侧看到已读回执。
2. **历史页有真实记录**:`/hands` 是全局的(冒烟与既有用例已经打过很多手),断言列表渲染出**真实行**并且字段可读,而不是「空态也算过」。
3. **改密码真执行**:在设置页把密码**改成同一个值**(`devpass123` → `devpass123`)。它是幂等的,所以可重复跑、也不破坏别的用例;验的是「表单 → 信封 → 后端 → 成功提示」这条链真的通,以及 0097 之后的成功文案(会提示其它设备被登出)。

## 实际改了什么

新增 `frontend/e2e/dm-and-account.spec.ts`,三条用例,**代码零改动**——这一批只加验证。

三条都按计划落地(私聊两人真收发 / 历史页有真实记录 / 改密真执行)。**改昵称按计划未做**,原因见上。

### 写的过程中被三个真实约束纠正

1. **不能 `page.goto('/settings')`**。三条用例第一版全栽在第一个元素上,连 `/settings` 里明明存在的「旧密码」都找不到。原因是**会话只在内存里**(`transport/session.ts` 的模块级变量),整页加载会把它清掉,路由守卫随即把人弹回登录页——所以页面确实没渲染。改成和既有用例一样**点进去**(`getByTestId('history-entry')` / `profile-card`)。这条已写进 spec 的注释,它是这套前端的通用约束,不是本用例的特例。
2. **抽屉是 `<aside>` 不是 dialog**:`getByRole('dialog')` 找不到,应为 `complementary`。
3. **两处 strict-mode 撞多个元素**——而这其实是**好消息**:正文同时出现在气泡与左侧会话预览里,「其它设备」同时出现在表单上方的静态说明与成功提示里,说明元素都在。断言按语义收窄,而不是无脑 `.first()`:改密那条特意匹配**成功提示整句**(`密码已更新。你在其它设备上的登录已被退出`),因为静态说明里也有「其它设备」,裸匹配会让这条断言在文案退化时照样绿。
