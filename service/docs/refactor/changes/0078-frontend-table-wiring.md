# 0078 · 牌桌页接线 + 端到端跑通

日期:2026-08-17 · 性质:**前端建设**(后端零改动)· 触发:承接 [0077](0077-frontend-kickoff.md) 的待办第 1、2、3 条。

## 结论一句话

牌桌页从本地 mock 改成**完全由服务器驱动**,本地发牌与街道推进整套删除;补了状态归并与 seq 纪律的单测(46 项全绿);最重要的是**端到端跑通了**——用前端自己的加密代码对真后端完成登录 → ws 握手 → 进房 → 入座 → 买入 → 准备 → 开局 → 打完一手 → 聊天 → 离桌,并验证了底牌隐私、seq 单调、离桌后筹码守恒。

## 一、状态层

新增 `src/store/`:

- **`room.ts`** —— `StateSnapshot` 整份替换 + 各事件的增量归并。这一层**不复算任何规则**:谁能行动、底池多少、谁赢,全部照抄服务器字段。
- **`actions.ts`** —— 界面操作翻译成 `ClientMessage`,发完就结束;界面等服务器回事件再变,不抢先改本地状态。
- **`useRoom.ts`** —— `useSyncExternalStore` 订阅。不引状态库:状态只有一个写入口(服务器消息),组件只读。

两处需要留神的归并规则,已写进注释并有测试钉住:

- **快照不带 `last_bet`**,本街要跟多少由各家 `bet_amount` 的最大值还原。
- **街道推进要清各家本街投入和需跟额,但不清底池**——底池是累计的。

## 二、牌桌页

保留全部设计好的 JSX 标记,只换数据源。删掉的东西:

- `createDeck` 本地发牌、`advanceToFlop/Turn/River/Showdown` 手动推进街道的临时按钮、`handleSetAllReadyTest` 一键全体准备。街道由服务器的 `hand_status_changed` 驱动,准备状态是服务器的,前端不能代改。
- `src/utils/poker.ts` 里的 `createDeck`/`shuffleDeck`/`evaluateHand` 一并删除,只留 `formatChips`。留着这些会诱使人再去本地算一遍,而本地算一遍就必然和服务器分叉。

新增的界面(原设计假定玩家已经坐好了,真实流程少不了这两步):

- 未入座时提示「观战中 · 点桌上空位入座」,点空位发 `sit_down`。
- 已入座但桌上没筹码时出现买入输入框,发 `buy_in`;没买入前 Ready 按钮禁用。
- 服务器拒绝某个操作时把 `ErrorCode` 显示出来(后端只回机器码,文案归前端映射)。

**协议与界面的两处换算**,都收在一处做,不许各自转换:

- 座位号界面 1 起、协议 0 起。
- 牌面类型:协议 `{rank:'T', suit:'h'}` ↔ UI `{rank:'10', suit:'hearts'}`(牌面图按 `10h.png` 命名)。适配器在 `src/utils/card.ts`,这就是 0076 记的 M7 的解法——协议面用 `wire.gen.ts`,`poker.ts` 退回纯 UI 用途。

## 三、补测(0077 自 review ⑥ 点名的缺口)

从 29 项加到 **46 项**:

## 四、端到端冒烟(`npm run smoke`)

**这是本次最有价值的部分。** 类型检查和构建都发现不了「密钥派生错一个字节」这类问题,而它的表现只是服务器默默关连接、没有任何有用报错。

`frontend/scripts/smoke-e2e.mjs` 用本前端自己的 `src/crypto` 打包出来跑,对真后端逐项验:

```
✓ 登录换回 session_id + session_token
✓ 两条加密连接建立
✓ 收到 StateSnapshot(房间=smoke-xxx, 座位数=6)
✓ 买入到账(bob 桌上 500)
✓ 开局(2 人,button=1)
✓ alice 收到自己的两张底牌
✓ alice 收不到别人的底牌
✓ 手牌结束(赢家 alice+2)
✓ bob 收到 alice 的聊天
✓ alice 收 21 帧, bob 收 14 帧,均严格递增
✓ 离桌后筹码守恒:alice=1004 bob=996,合计 2000
```

### 冒烟过程中发现的三件事

**1. 本地 dev 库过时,后端根本起不来。** `service/poker.db` 是加鉴权列之前建的(只有 `id/nickname/points` 三列),`no such column: user.name` 直接启动失败。旧库未被 git 跟踪、只有 6 个种子用户,已备份后按 `alembic upgrade head` 重建(六支迁移全部跑通)——按 [db-migrations.md](../../db-migrations.md) 的正确路径走迁移,而不是让 `create_all` 建一个没有迁移历史的表。重建方式已写进 [frontend/docs/dev.md](../../../../frontend/docs/dev.md)。

**2. 「上一次会话的残留」是前端必须处理的真实场景。** 第二次跑冒烟时失败:上一轮 alice 是**在座**断线,后端按不变量 9(一个用户同时只在一个房间)保留了她的座位,于是新连接走的是**重连**路径,服务器先发来**旧房间**的快照,此时 `join_room` 到新房会被 `ALREADY_IN_ROOM` 拒掉。

这不是后端的 bug,是正确行为。前端真实场景同理:用户重登后可能还挂在上次的房间里。冒烟脚本现在先看快照里的房名,不对就先 `leave_room` 再进。**这条也要落进牌桌页**,已登在待办。

**3. 我自己的断言写错了一次。** 冒烟最后断言「alice 积分回到 1000」,实际是 1001——因为她赢了这手。该断言的是**守恒**(两人合计仍是 2000),这也正是后端的核心不变量。改对之后连跑两次都通过。

## 五、续做:残留自愈 + 冒烟扩展 + 一个真 bug

本篇提交后接着做完了原列的第 1、2 条,并因此抓到一个我自己写错的地方。

### 5.1 「上次会话残留」已自愈(原 0078·A)

`store/joinFlow.ts` 抽出纯函数 `decideJoinMessage`,收到**别的房间的快照**或 `ALREADY_IN_ROOM` 都判为「先退再进」,并且**只做一次**(做不成就把错误交给界面,不反复重试转圈)。`actions.ts` 照此处置,旧房快照不并进本地状态。

`scripts/smoke-stale-room.mjs` 在真后端上验:alice 进 A 房入座后直接断线 → 重登目标 B 房 → 服务器果然先发 A 房快照 → 前端识别并恢复 → 最终落在 B 房。

### 5.2 冒烟从「一方 fold」扩展到完整摊牌(原 0078·B)

改成按需跟注推进,现在覆盖 preflop → flop → turn → river → 摊牌比牌:

```
✓ 手牌结束(alice+4)
✓ 走完三条街道(pre_flop → flop → turn → river)
✓ 摊牌亮 2 家底牌、公共牌 5 张
✓ 离桌后筹码守恒:alice=1002 bob=998,合计 2000
```

### 5.3 抓到的真 bug:`acting_position` 不是座位号

扩展冒烟后手牌卡在 preflop,服务器回 `NOT_YOUR_TURN`。查下来是我理解错了协议:

> **`acting_position` 是 `players[]` 的下标,不是座位号。**([wire-protocol-guide.md](../../wire-protocol-guide.md))

`players` 按**行动序**排([0] 是小盲),座位号是桌上的**物理位置**,两者一般不等。我的 `isMyTurn` 却拿 `acting_position` 直接和 `seat_position` 比——**只在「下标恰好等于座位号」时才对**。

更值得记的是**为什么单测没抓到**:我的夹具里 alice 坐 0 号位是 `players[0]`、bob 坐 1 号位是 `players[1]`,下标恰好等于座位号,于是错的实现也能通过。修复时把夹具改成 alice 坐 3 号位、bob 坐 5 号位,让这类混淆再也躲不过去,并新增 `actingPlayer()` 把换算收在一处。

**教训**:夹具里让两个语义不同的数字取相同值,等于把 bug 关在测试之外。端到端冒烟能抓到,正是因为真后端不会迁就我的误解。
