## §B 部署手册:新文档 [docs/deploy.md](../../deploy.md)

覆盖:Ubuntu 24.04 系统准备 → pg 建库迁移(按编号引用 [db-migrations.md](../../db-migrations.md) §0,不复述)→ 后端(poetry / 生产 `poker.env` / **dev 种子的安全善后**)→ 正式账号与 K_user 轮换 cron → 前端(**`NEXT_PUBLIC_API_URL` 是构建期烤进产物的**、CORS 配对、nginx 同源反代含 ws 升级头)→ systemd(单 worker 铁律、TimeoutStopSec 给 drain 留时间)→ 运维(405 即活的验活逻辑、json 日志 + **CRITICAL 才值得告警**、pg_dump 备份 cron 与丢失窗口、升级/回滚流程)→ 迁移(sqlite→pg 含 tz 与序列两坑、设备到设备的五样清单与切换时序)→ 边界(无 TLS 内网设计、单进程、重启语义)。

**写法上的约束**:数据库层一个字不复述,全部按编号指向 db-migrations.md §0——那节是 0095 在 pg 16 上实跑验证过的,本篇再抄一遍就是第二事实源。手册里每一条「事实陈述」都对着代码或既有文档核过,其中三条是本批读代码新确认的:

1. `NEXT_PUBLIC_API_URL` 经 `next.config.js` 的 `env` 段在**构建期**固化——换后端地址必须重 build(不是改环境变量重启)。
2. `CORS_ORIGINS` 在 `app/config.py`,默认只放行本机 3000 的两种写法;同源反代时留空。
3. `seed_dev_users` 的幂等 INSERT 意味着 **§0.6 的 DELETE 会在每次重启被种回**——所以手册的口径是「首跑前换强密钥、账号留着」,而不是照 §0.6 删了了事;这一条也回填进了 A4 的缺口表。
