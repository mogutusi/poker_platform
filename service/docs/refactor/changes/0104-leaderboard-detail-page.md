# 0104 · 排行榜详情页(0081·D)

日期:2026-08-28 · 性质:**前端功能**· 触发:[TODO.md](../TODO.md) 0081·D —— 大厅「查看完整排行」一直是**禁用占位**(标着「待建」、`disabled`),这是 0081 有意的做法:**不指向一个不存在的路由**,不造假链接。现在把它兑现。

## 现状与要补的

大厅按设计规则是「摘要 + 入口」([changes/0081](0081-lobby-hub-settings-history-dm.md)):每个模块在大厅只给摘要,点进去看全量。五个模块里四个已经有详情页(`/settings`、`/history`,牌桌与私聊各有归属),**只有排行榜的入口是死的**。

数据端不用做:`POST /leaderboard`(0050 落地,0094 收进信封)已经在跑,前端 `transport/rest.ts` 的 `fetchLeaderboard(limit?)` 也现成——大厅摘要就在用它。缺的纯是那一页。

## 打算怎么改

新建 `/leaderboard` 页,照 `/history` 的既有骨架(loading / 空态 / 错误 / 返回大厅),内容上做三件事:

1. **拉全量**:`fetchLeaderboard(LEADERBOARD_PAGE_SIZE)`。后端 `LEADERBOARD_MAX_LIMIT=100`,而 0094 之后**越界是 400、不是截断**,所以这个数不能瞎填。
2. **标出「我」**:同 `/history` 的做法,把自己那一行高亮——一屏几十行里找自己是这页的主要用途。
3. **口径照抄大厅那句**:「榜上是结算后的全局积分,**不含桌上筹码**」。[rest.md](../../rest.md) 专门记了这个坑(把积分全买上桌的人排名会掉得很难看),大厅写了,详情页不写就成了两套说法。

然后把大厅那个 `disabled` 占位换成真链接。

### 一处躲不掉的第二事实源,先说清

`LEADERBOARD_PAGE_SIZE = 100` 是**手抄后端的 `LEADERBOARD_MAX_LIMIT`**。这正是 0099 刚清理过的那类毛病,但这次躲不掉:REST DTO 与其边界**没有 codegen**(0094 之后 OpenAPI 里只剩信封,`openapi-typescript` 那条路是关的,见 [rest.md](../../rest.md) 共同原则 4)。所以做法是:命名常量 + 注释写明它对应哪个后端配置、以及超了会 400 而不是被截断。记在这里,不假装它不存在。

## 实际改了什么

- **新建 `frontend/src/app/leaderboard/page.tsx`**:骨架照 `/history`(loading / 空态 / 错误 / 返回大厅),内容是名次列表,自己那行高亮并标「你」。两个请求**分开发**:排行榜是正题,`/user/me` 只为高亮,它失败不该让整页空着——同 `/history` 的既有做法。
- **大厅入口**从 `disabled` 占位换成真按钮,`onClick` 推 `/leaderboard`。
- **e2e**:`hub.spec.ts` 加一条(该 spec 本就是「大厅枢纽 + 详情页」的归属)。

### 一个撞车,以及为什么值得记

按钮我一开始给了 `data-testid="leaderboard-entry"`,结果 strict mode 报**撞了 6 个**——大厅摘要的每一行早就在用这个 testid(5 行 + 我这个按钮),而 `journey.spec.ts` 也在用它。改成 `leaderboard-more`。
**记它是因为**:那 5 行的 testid 是「摘要行」的语义,我这个是「去详情页」的入口,同名等于把两个不同的东西混成一个选择器——`journey.spec` 那条 `.first()` 恰好没被我搞坏,纯属运气。

### 名次不在前端排

列表**原样渲染后端给的 `rank`**,不本地排序。后端同分按昵称升序定序([rest.md](../../rest.md)),前端再排一次就会两处说法不一。用例因此断言「第一行是 `#1`」而不是「第一行积分最高」。

## 自 review

按 [review.md](../../review.md) 七维。本批是**前端加一页**,最高风险面是「口径与大厅不一致」和「前端偷偷重算了服务器该给的东西」。

- **① 分层 / 不变量**:后端零改动。前端不变量 1「不复算规则」:名次、积分、定序全部原样用后端的,**前端不排序、不算分**。数据只经 `transport/rest` 的既有 `fetchLeaderboard`,组件不碰网络。
- **② 代码↔文档同步**:页面把 [rest.md](../../rest.md) 记的那个坑(排的是结算后积分、不含桌上筹码)照抄成用户可见的一句话,并在注释里指回出处。
- **③ 文档↔文档一致**:[TODO.md](../TODO.md) 的 0081·D 勾掉。
- **④ 数据模型正确性**:直接用 `transport/rest` 的 `LeaderboardEntry`,不另立一份形状——注意**大厅自己有一个本地 `LeaderboardEntry{name,points}`**(只为摘要那几行),我没有复用它,否则就把 `rank` 丢了。
- **⑤ 规范合规**:注释讲「为什么」(为什么两个请求分开发、为什么不本地排序、为什么 `PAGE_SIZE` 是手抄的)。
- **⑥ 测试充分**:2 处变异确认。**如实记缺口**:(a) 用例断言「行数 > 1」而不是某个确定值——榜长依赖库里有多少账号,写死会脆;代价是「详情页比摘要长」这条只被弱断言(摘要是 5 条,库里有 10 个 dev 账号,所以 >1 能过但不能证明 >5)。要强断言得先固定数据集。(b) 空态与错误态没有用例覆盖,它们只在「库空」或「后端挂」时出现,当前环境造不出来。
- **⑦ 流程账本**:变更记录先行;testid 撞车这个计划外的坑写进了记录,因为它暴露的是「摘要行与入口共用一个 testid」这种会误导后来者的命名。

### 一处躲不掉的第二事实源(重申)

`LEADERBOARD_PAGE_SIZE = 100` 手抄后端的 `LEADERBOARD_MAX_LIMIT`。REST 的边界没有 codegen(0094 之后 OpenAPI 里只剩信封),所以只能命名 + 注释写明出处与「越界是 400 不是截断」。**后端调小这个上限,这一页会开始报错而没有任何测试会先红**——这条缺口如实记下。
