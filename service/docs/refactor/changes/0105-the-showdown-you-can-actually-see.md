# 0105 · 摊牌从来没有被看见过

日期:2026-08-28 · 性质:**缺陷修复(前端渲染)**· 触发:[changes/0087](0087-reconnect-and-displacement-in-browser.md)「有意不做」段记档的那条 ——「摊牌亮牌在界面上几乎看不见……是界面该给一个『结算展示期』。记档,未登记为缺陷(不是「会错」,是「没做」)」。

## 登记说「几乎看不见」,实测是**一次都没看见过**

0087 只看到一半。开工前用 `MutationObserver` 记下整手牌里 DOM 上每一次牌面变化(alice/bob 真浏览器、真后端,探针见「验证」),拿到的序列是:

```
…402393  ["5h","7c","8c","Kd","Ks","Qc","Qs"]                      河牌:自己 2 张 + 公共 5 张
…402725  [… 同上 7 张 …, "back.png", "back.png"]                   摊牌:对手的两张牌**是牌背**
…402731  []                                                        6 毫秒后:整桌清空
```

两个**互相独立**的原因,各自都足以让摊牌不可见:

| # | 原因 | 位置 | 后果 |
|---|---|---|---|
| A | `hand_ended` 一到 `handStatus` 变 `null` ⇒ `gameStarted` 转假,牌面/公共牌/底池整块卸载 | `game/page.tsx` 的 `gameStarted` 闸门 | 桌子在 **6ms** 后清空(实测) |
| B | 别人座位的牌**硬写** `isHidden` | `game/page.tsx` 非 `isCurrent` 分支 | 就算给你那 6ms,你看到的也是**牌背** |

所以 0087 记的「闪一下」还乐观了:那一闪里闪的是两张牌背。**`state.reveals` 自它存在以来,一次都没有渲染出过一张正面朝上的对手牌。**

### B 是**代码与文档打架**,不是「没做」

[frontend/BACKEND_GUIDE.md](../../../../frontend/BACKEND_GUIDE.md) 写的是契约口径:

> 渲染时对手的牌一律牌背,**摊牌才翻**。

代码从来没有「翻」的那一半。按本仓的口径(见 [coding_principle.md](../../coding_principle.md)「代码用了非文档的结构,必须当场改文档」),文档与代码不一致是**缺陷**。

(收工时复审指出这句我只说对了一半:「一律牌背」那半代码同样没做,而且本批也没做——详见自 review ②。)

### A 也不是有意设计

按房规「A/B/C 都做了 X 唯独 D 没做时,先假设 D 是有意的」,专门查了一路:全仓(`service/docs`、`frontend/docs`、`changes/`、两份指南)**没有任何一句**说「两手之间桌面应当清空」或「亮牌只在 `SHOWDOWN` 状态显示」。相反,[frontend/docs/state.md](../../../../frontend/docs/state.md) 的事件表把「清上一手的展示」明确挂在 **`HandStarted`** 那一行,而 store 也正是这么实现的:`hand_started` 清 `board`/`reveals`/`lastResult`,`hand_ended` **一个都不清**。

也就是说 store 早就为「结算展示期」准备好了,只有视图层提前把闸门关了。A 是 0078 把 mockup 那个只会变真的手动 `gameStarted` 标志改写成 `state.handStatus !== null` 时的未记档副作用(`git show 7506aae` 里 `setGameStarted` 唯一的调用是 `setGameStarted(true)`)。

## 打算怎么改

**只动视图层,不动 store、不动协议、不动后端。** store 已经把数据留到下一手了(`hand_ended` 的 patch 只有四个键),要做的是让渲染跟上。

1. **B(翻牌)**:把「谁的牌能朝上」变成一个有判据的问题——判据是**服务器给没给这张牌**,不是本地推断谁该亮牌。(第一版按座位号索引,自 review 抓出这是错的,见下。)
2. **A(展示期)**:新增派生量 `showingShowdown = !gameStarted && state.reveals.length > 0`,牌面与公共牌的闸门从 `gameStarted` 换成 `gameStarted || showingShowdown`。`reveals` 只由 `hand_show_down` 写,清它的只有 `hand_started` / `state_snapshot` / `resetRoom`,所以「非空」**精确等于**「这一手摊过牌、且新一手还没开始」——不需要新的状态,也不需要计时器。
3. **e2e**:在 `showdown.spec.ts`(它本来就叫「打到摊牌」)补断言:手牌结束后正面朝上的牌是 **9** 张(自己 2 + 公共 5 + 对手 2),并且**关掉结算面板之后仍然是 9** —— 后者才是「留在桌上」的真正判据(`clearResult` 只清 `lastResult`,不碰 `reveals`)。
4. **文档**:[frontend/docs/state.md](../../../../frontend/docs/state.md) 的 `HandEnded` 行补上「结算展示期」这一条,并写明清点仍在 `HandStarted`。

### 边界:先说清哪些**故意不做**

- **底池不留**。`hand_ended` 之后底池已经付出去了,继续显示「底池 30」会让人以为桌上还有钱;赢了多少由 `HandResult` 面板说。所以底池闸门仍是 `gameStarted`。
- **无摊牌结束(有人弃牌收尾)不留展示期**。那种牌局没有 `reveals`,没有任何别人的牌可亮,留一份公共牌只是把「上一手」和「这一手」混在一起。
- **展示期内重连会丢**。`state_snapshot` 清 `reveals`(服务器不保存已结束手牌的摊牌),所以展示期中途重连就没了。这是如实的:服务器确实不再持有那份数据,前端凭空留着才是编。

### 与建议不同的一处:不新增 dev 账号

并行调研建议「新开一个 spec + 追加两个 dev 账号(hana/iris)」。**不采纳**:`playwright.config.ts` 是 `workers: 1` + `fullyParallel: false`,而 `showdown.spec.ts` 本来就把手牌**打完**(不是停在局中),alice/bob 出房是干净的——0089 那个账号串扰的坑针对的是「结束时还停在手牌里」的用例,这条不属于那一类。改动 `DEV_USERS` 要动后端 env + 重启 + 播种,为一条断言付这个代价不值。断言加进既有那条用例即可,它的名字本来就是「打到摊牌」。

## 实际改了什么

四个计划内的改动都落地了,**外加三处计划外的**——其中第一处不做的话,这批等于没修成。

### 计划内

- **`frontend/src/app/game/page.tsx`**
  - 新增 `showingShowdown` / `tableCardsVisible` 两个派生量;公共牌、`hand` 投影、自己那两张、别人那两张,四处闸门从 `gameStarted` 换成 `tableCardsVisible`。
  - 原来那个混装的 `playerHands`(一个按座位号索引的 `Record`,自己的底牌和摊牌亮出来的牌都往里塞)**拆成两份**:`myHand`(自己的)与 `revealedHands`(摊牌的,**按昵称索引**)。为什么必须按昵称,见下「自 review 抓到的最重一条」。
  - 别人座位的 `isHidden` 从硬写改成 `!isRevealed`,判据是**服务器发没发这张牌**。
  - 新增「上一手摊牌」标签(`data-testid="showdown-recap"`),占底池腾出来的那个位置。
- **`frontend/e2e/showdown.spec.ts`**:那条用例本来就叫「打到摊牌」,断言补在它里面。按座位那条用**既有的** `data-seat` 钩子 + `FACE_UP_CARD`,不为测试新加生产标记。
- **`frontend/e2e/table.spec.ts`**:那条用例是**弃牌收尾**的手牌,补一句「桌面该清空」——把「没摊牌就没有展示期」这条边界钉住(此前只写在记录里,没有用例)。
- **`frontend/src/store/room.test.ts`**:两条新单测,分别钉住 `hand_started` 与 `state_snapshot` 各自清空 `reveals`。**这两次清空从本批起是隐私红线**(见 ⑥)。
- **[frontend/docs/state.md](../../../../frontend/docs/state.md)**:`HandShowDown` / `HandEnded` 两行改实 + 新增「结算展示期」一节;并在「UI 局部状态归谁」的清单里补上「服务器给的东西在屏幕上留多久」,否则那一节的交叉引用是空头支票。
- **[frontend/BACKEND_GUIDE.md](../../../../frontend/BACKEND_GUIDE.md) 与 [wire-protocol-guide.md](../../wire-protocol-guide.md)**:两处显示层口径改实(见自 review ②)。
- **台账**:[TODO.md](../TODO.md) 记完成 + 记新登记的 0105·A;[BUGS.md](../BUGS.md) 记新查出的 BUG-20 与 BUG-21。

### 计划外一:结算面板正压在公共牌上

改完先看了一眼截图——**摊牌是留住了,但五张公共牌被「本手结算」面板整个盖住**。面板原本 `absolute left-1/2 top-1/2` 挂在**页面根**上,而公共牌在牌桌容器的 `left-[63%]`,两者都落在桌子中央;以前不打架纯粹是因为那时候牌已经没了。

所以「看得见摊牌」会退化成「先把面板关掉才看得见」。改法:把 `<HandResult>` 的挂点从页面根挪进牌桌容器,位置改成 `left-[21%] top-[45%] w-72` —— 横向躲开 63% 的公共牌,纵向落在左列两个座位(30% / 60%)中间。

**这套位置是按 16/9 固定底图手调的,而且不是自动成立的**:面板定宽 288px,公共牌那排随容器缩放,窄到某个宽度以下必然重新相撞。实测 1280×720 只剩约 10px 余量,1440×900 宽裕。已把这句连同「改布局要肉眼复验」写进组件注释——第一版我在注释里写的是「挪进容器就不会窄屏相撞」,复审指出**这个理由不成立**,已改实。

**这条的教训**:改动只跑测试不看屏幕,就会交出一个「断言全绿、用户仍然看不见」的修复。0101 记过同一件事(那次是渐变色值),这次是遮挡。

### 计划外二:四处死码,复审又加两处

前三处是改的时候**直接踩到**的(就在要动的那几行上):

- `phase`(`state.handStatus ?? "preflop"`):算出来之后全文件零引用。
- `foldedSeats`:同上,一个 `useMemo` 零消费者。
- `PokerCard` 的 `cornerLabel`:声明在 props 接口里,**但组件签名根本没解构它**——所以两个调用点传了个寂寞。删掉 prop 与两处传参,顺手给 `isHidden`/`size` 补上含义注释(规范要求;`card`/`className` 自明,没加)。

删完这三处顺手把整个文件扫了一遍局部变量,又抓到第四处:

- `seatChoice`:`useState` 的值**只写不读**(全文件唯一出现就是那行声明,`setSeatChoice` 在点击空座时被调一次)。写一个没人读的 state 还白搭一次重渲染。连同那次调用一起删。

**复审又抓出两个死类型**:`interface Seat` 与 `interface SeatPlayer`(文件顶上)零消费者,而且 `Seat` 的形状早就和代码实际构造的对象对不上了。一并删。

扫的时候踩到一个**方法坑,值得记**:本机的 `grep` 是 ugrep 包装、默认按词匹配,`grep -n seatChoice` **数不到** `setSeatChoice`。改用 python 逐行 `in` 才拿到真相。**在这台机器上,凡是「数引用」的结论都别只信 `grep`**——0099/0102 的删除类改动正是靠数引用定案的。

另外 `game/page.tsx` 顶上那段 `useSearchParams` 的注释在 HEAD 里就是**重复贴了两遍**,一并去重。

### 计划外三:「Folded」标会挂到下一手

`currentPlayerFolded` 读的是 `state.players`,而 `hand_ended` 不清它。原来没有闸门,所以弃过牌的人在**两手之间**一直挂着「Folded」和那层变暗——那时他并不在任何一手里。既然本批正在定义「什么时候桌上有牌可谈」,就把这两处一起收进 `tableCardsVisible`。

### 自 review 抓到的最重一条:按座位号索引,展示期里会张冠李戴

第一版把摊牌的牌**按座位号**索引(`revealedSeats: Set<number>` + `playerHands[seat.number]`)。对抗复审指出:**结算展示期恰恰跨越了两手之间,而那段时间里座位会易主。**

路径是通的,而且全是既有行为:亮过牌的人两手之间 `leave_room` → 不在手里,`_begin_leave` 直接 `_evict` → 广播 `UserLeft` → 前端把他从 `seats` 里删掉 → 观战者点那个空座 `sit_down` → `UserStatusChanged` 在**同一个座位号**上插进新人。而 `reveals` 一个字没变。于是新占座的人身上会挂着**上一手另一个人的底牌,正面朝上**。

牌本身是公开的(摊牌对全房公开),错的是**归属**:界面在说一句服务器从没说过的话。而这是 0105 自己造出来的——0105 之前展示期不存在,`gameStarted` 早就把牌收掉了。

**实测复现过,不是推理**(三个上下文:alice/bob 打到摊牌 → bob 离桌 → gina 坐进 2 号座):

| 索引方式 | 2 号座渲染出的牌面图 | 判定 |
|---|---|---|
| 按座位号(第一版) | **2 张**,且带着「已亮牌」标记 | 张冠李戴 |
| 按昵称(现在) | **0 张** | 干净 |

改法:`revealedHands` 改成 `Map<nickname, cards>`,座位取牌时用 `seat.player.name` 查。昵称是 `world` 的键、全局唯一,且房内不能改名,所以它是这里唯一稳定的身份。**失败方向也对**:查不到就是 `undefined` → `hand = []` → 什么都不画,而不是画错。

### 复审实测出的另一个缺陷:登记,不修

对抗复审顺着「桌上还显示什么」查下去,**实测**出座位卡片上的筹码从入座那一刻起就不再变(整手牌 + 结算后三次采样全是 `100 / 100`,而结算面板同时写着「你赢了 4」)。它有一半要动协议(结算后的座位筹码在 wire 上没有承载),**与本批无依赖**,已登记为 [BUGS.md](../BUGS.md) **BUG-20**,不在这批修——混一个动协议的改动进来,会让本批的变异验证和复审一起失焦。

### 实测证据(三份,都不是从代码推的)

1. **开工前的探针**(一次性,已删):在 A 页面挂 `MutationObserver`,每次 DOM 变化记一份牌面快照。本篇开头那段序列就是它的输出,也是「6 毫秒」和「那一闪是两张牌背」的来源。
2. **改完的同一支探针**:末尾停在 `["4d","4s","6c","6h","8h","8s","9d","Kd","Qh"]` —— 9 张,**零 `back.png`**,后面不再出现清空(改之前那一行是 `[]`)。
3. **座位易主探针**(一次性,已删):三个上下文跑「摊牌 → bob 离桌 → gina 坐进 2 号座」,按座位号索引时 2 号座渲染出 **2 张**别人的牌,按昵称索引时 **0 张**。这条既证伪了第一版,也证实了修法。

**肉眼确认**(1280×720 与 1440×900 各一组截图):面板还在时五张公共牌完整可见、对手底牌正面朝上;关掉面板之后牌还在。1280 下面板右缘到公共牌左缘实测约 **10px** 余量。

### 反向变异验证 8 处

每一处都单独跑,并按**行号 / 用例名**确认变红的是哪一条(不靠总数推断):

| 变异 | 变红的 |
|---|---|
| 别人座位的 `isHidden` 退回硬写(退回原因 B) | `showdown.spec` 第 67 行 `toHaveCount(9)` —— 实收 **7** |
| `tableCardsVisible` 退回 `gameStarted`(退回原因 A) | 同上第 67 行 —— 实收 **0** |
| `clearResult` 顺手清掉 `reveals`(伪造「牌跟着面板一起活」) | 第 78 行,即**关掉面板之后**那条;第 67 行仍绿 |
| 亮牌改回按座位号索引 | 座位易主探针:2 号座从 0 张变 **2 张**(见上证据 3) |
| 去掉「上一手摊牌」标签 | 第 72 行 `showdown-recap` |
| `hand_started` 不再清 `reveals` | vitest `新一手开始必须清掉上一手的亮牌…` |
| `state_snapshot` 不再清 `reveals` | vitest `重连拿到的快照也清亮牌…` |
| 展示期永远开着(`showingShowdown = !gameStarted`) | `table.spec`(弃牌收尾那条)`toHaveCount(0)` —— 实收 **2** |

前两条各自证明**两个原因确实互相独立**:任修一个,另一个都会让同一条断言以不同的数字(7 / 0)失败。

**一处变异杀不掉,如实记**:把展示期判据从 `reveals.length > 0` 换成 `board.length > 0`,全套仍然全绿。原因是 e2e 里所有的弃牌都发生在 **preflop**,那时 `board` 本来就是空的,两个判据碰巧同真。要杀它得有一条「翻牌后才弃牌收尾」的用例。

## 自 review

按 [review.md](../../review.md) 七维。本批是**纯前端渲染修复**,最高风险面是三个:「是不是在替服务器编数据」「有没有把还开着的设计决策当 bug 改掉」「测试是不是真的能红」。

方法上仍用并行多 agent 对抗式复审(四组维度 → 每条发现再找独立视角试图证伪)。**这一轮抓到的最重一条是我自己修出来的**——见上「按座位号索引」那节,它是本批新造的缺陷,不是既有的。

- **① 分层 / 不变量**:后端一行未动(`service/` 只有 .md 变化),core 与协议零改动。**前端不变量 1(不复算规则)**:留在屏幕上的每一张牌都是服务器发过来的原样——公共牌来自 `board`,亮牌来自 `reveals`,翻不翻的判据是「服务器发没发这张牌」。`showingShowdown` 是**展示窗口**,state.md 的「UI 局部状态归谁」现在把这一类明确列进去了(第一版我引用了那一节,但那节的清单里其实没有这一项,等于引了个空头支票,已补)。不变量 2(快照即真相)未破:`state_snapshot` 照旧整份替换并清空 `reveals`,所以展示期中途重连会失去摊牌——**这是对的**,服务器确实不再持有它。
  **这一维第一版漏掉的就是那条最重的**:我核了「有没有编数据」,却没核「这些数据挂在谁身上」。座位号在展示期里不是稳定身份,而展示期正是本批造出来的。教训:**新开一个显示窗口,就要把窗口里每一处 join 的键重新问一遍**——窗口外成立的键,窗口内未必成立。

### 对抗核实:有没有把一个有意的设计当 bug 改掉

这是房规点名的风险(0074 的教训),专门反过来查了一遍,结论是**没有**:

- 全仓没有任何一句说「两手之间桌面应当清空」或「亮牌只在 `SHOWDOWN` 状态显示」。
- 唯一沾边的成文规定是 state.md 事件表把「清上一手的展示」挂在 **`HandStarted`**,而 store **一直就是这么实现的**。也就是说 store 早就按「展示期」写好了,只有视图层提前关了闸门——本批是让视图追上 store,不是反过来。
- 0087 的原话是「**是界面该给一个『结算展示期』**」,那是「该做没做」,不是「决定不做」。
- 原因 B 更明确:两份指南都写着「摊牌才翻」,代码不翻是**违约**。
