# 0086 · 退役明文 dev 端点 + 把两处口径改实

日期:2026-08-24 · 性质:**安全收尾 + 决策记档**· 触发:用户定案三条(见下)。

## 用户定案(对话里定的,按 README §5 记进来)

1. **不做注册端点,是有意的。** 用户原话:「我只靠单独添加 user 表行来内部注册」。所以「没有开户接口」不是缺口,是既定的运营方式——内部人直接往 `user` 表插行,`K_user` 由管理员 CLI `scripts/kuser_admin.py issue` 带外发放。**这条要写进设计文档**,否则下一个人会把它当成待办去实现。
2. **明文端点确认可以关掉**:前提是前端加解密做完了。已核实(见下),故本批退役。
3. **CI 那条我说重了。** 仓库确实有 [dev.md](../../dev.md)「提交」一节写明提交规约;缺的不是「怎么提交没写」,而是**没有自动化把它兜住**。所以本批只把 [architecture.md](../../architecture.md)/[wire.md](../../wire.md) 里「codegen 进 CI/pre-commit」这句**不实的口径改实**(实际是 pytest 守门),不去搭 CI —— 那是另一个决策,不该顺手做掉。

## 退役前置条件的核实

[connection.md](../../connection.md) 写的退役条件是「前端切加密后退役明文 `?nick=` 端点」。逐条核过:

| 条件 | 核实结果 |
|---|---|
| 前端只连加密端点 | `src/transport/config.ts` 只产 `/ws?sid=`;`frontend/src`、`frontend/scripts`、`frontend/e2e` 全仓 **0 处** 引用 `/dev/ws` |
| 前端加解密真的能用 | `npx vitest run src/crypto` **29/29** 后端生成的向量通过;三条冒烟 + 13 个浏览器用例全部走真加密信道 |
| 后端还有谁依赖它 | 只有两个测试:`test_secure_channel_wiring.py`(断言两个端点并存)、`test_persist_barrier.py`(拿它驱动一次载入屏障) |

## 为什么值得现在关

`/dev/ws?nick=` **无鉴权**:握手只看 `?nick=` 是不是 dev 用户名,谁连上都能冒充那个身份收发命令。它从 [0018](0018-d-dev-shell.md) 起就标着 dev-only、绝不上线,但「标着」不是防线——只要进程里还注册着这条路由,一次配置疏忽就够了。退役条件既然满足,留着只有风险没有收益。

## 打算怎么改

- `app/shell/lifespan.py`:删 `/dev/ws` 端点 + 模块头的跑法说明改成加密端点。
- **`Connection.channel is None` 的明文帧路径保留**,但重新定性:它不再是「dev 端点模式」,而是**测试接缝**——shell 层大量测试用 `FakeWS` 走明文帧,逼它们全部套一层加密只会让接线测试变得难读,而且加密本身在 `tests/crypto` 已穷举。要在注释里写清楚这个转变,否则读者会以为还有明文入口。
- 两个测试改掉:一个改成断言 `/dev/ws` **不再注册**(退役的回归护栏),一个改用加密端点驱动。
- 文档:[dev.md](../../dev.md)(跑法)、[connection.md](../../connection.md)(退役项兑现)、[wire-protocol-guide.md](../../wire-protocol-guide.md) §9、[frontend/BACKEND_GUIDE.md](../../../../frontend/BACKEND_GUIDE.md) §4.5「开发期捷径」。
- 决策记档:内部注册写进 [user.md](../../user.md) / [auth.md](../../auth.md)。
- [BUGS.md](../BUGS.md) DEBT-1 口径改实。

## 实际改了什么

三件按计划做完,外加一件验证过程逼出来的。

### 1. 明文端点退役(`app/shell/lifespan.py`)

删掉 `/dev/ws` 端点本体,连带删掉只为它存在的 `load_user_by_nick` import。`create_app` 现在只注册 `/ws?sid=` 一条 ws 入口。实测 `curl /dev/ws?nick=alice` → **404**。

**`Connection.channel is None` 的明文帧路径保留,但重新定性成「测试接缝」。** 生产已经走不到它(唯一入口必带 channel),但 shell 层大量接线测试靠 `FakeWS` 走明文帧;逼它们全部套一层加密只会让「验的是接线」这件事被加密细节淹没,而加密本身在 `tests/crypto` 已穷举 24 项。`connection.py` / `receiver.py` / `sender.py` 三处注释都改成这个口径——否则读者会以为还有明文入口。

**退役有回归护栏**:`test_secure_ws_route_registered_and_plaintext_one_is_gone` 断言 `/dev/ws` **不再注册**。谁要是"为了本地方便"把它加回来,这条就红。

另一条测试(`test_ws_endpoints_wire_persistwriter`)原来拿明文端点驱动一次载入屏障,改成用两个加密会话驱动,保住原本要钉的东西(两条连接都必须拿到 `persistwriter`,否则 0073 的载入屏障静默跳过)。

### 2. 内部注册决策记档([user.md](../../user.md))

新开一节「账号从哪来:**内部注册,没有开户接口**」,写明这是有意设计、别去实现注册端点,并推出两条读代码时容易误判的推论:登录端点查不到 `name` 就 401 而不是建号;`_build_join` 读不到 DB 行回 `INTERNAL` 而不是当新用户。

### 3. CI 口径改实([architecture.md](../../architecture.md) / [wire.md](../../wire.md) / DEBT-1)

两处「生成步骤进 CI / pre-commit」改成如实:守门是 `pytest` 里的 `test_codegen_uptodate.py`,**仓库没有 CI 也没装 pre-commit**,提交规约写在 [dev.md](../../dev.md)「提交」靠人执行。要不要真搭 CI 是独立决策,本批不做。DEBT-1 划掉。

### 4. 顺带修:冒烟与浏览器用例共用账号会互相打红

退役后跑验证时,主冒烟红了一次:「离桌后筹码守恒 …… 合计 1410(跑之前 1210)」——总额**变多**了 200。查下来与本批无关:浏览器用例结束时玩家还坐在桌上,占座窗口满后 `Cleanup` 把桌上筹码退回全局积分,而这笔退款正好落在冒烟跑到一半的时候。

这是 0079 那条教训(「共享后端状态的测试之间,账号必须隔离」)的**第二种形态**:那次是连接互相顶替,这次是**筹码**跨测试流动。而且更难查——产品完全没问题,红的原因在另一个测试里。

修法:`DEV_USERS` 追加三个**冒烟专属**账号 `smoke1/2/3`,三条冒烟全部改用它们,浏览器用例继续用 `alice`..`frank`。验证方式就是复现那个场景:**先跑完整浏览器套件,紧接着跑冒烟** —— 修之前必红,修之后守恒稳定(2020 → 2020)。理由写进 [frontend/docs/dev.md](../../../../frontend/docs/dev.md) 和 `smoke-e2e.mjs` 头部。

顺带把 `smoke-raise-sidepot.mjs` 里写死的 `carol` 改成语义名(短码玩家),免得换账号时又留一处硬编码。

## 自 review

按 [review.md](../../review.md) 七维。本批性质是**减法 + 记档**,最高风险面是「删掉的东西是不是还有人用」与「文档里是不是还留着指向它的路标」。

- **① 分层 / 不变量**:删的是一条 ws 路由,不碰 core、不碰任何不变量。保留的明文帧分支已明确定性为测试接缝并在三处注释写清。
- **② 代码↔文档同步**:这是本批的重点。除设计文档外,**两处入口级文档差点漏掉**——`service/README.md` 和 `service/QUICKSTART.md` 都还在教人 `ws://…/dev/ws?nick=alice`,那是新人第一眼会照做的地方,留着就是把人送进一条已经不存在的路。全仓 `grep dev/ws` 复查,现存引用只剩「说明它已退役」的那几处 + 历史 changes(历史记录不改写)。
- **③ 文档↔文档一致**:[connection.md](../../connection.md) 那句「仅剩一项:前端切加密后退役明文端点」是这次退役的**依据**,已改成兑现记录;`wire-protocol-guide.md` §9、`BACKEND_GUIDE.md` §4 开头与 §4.5、§7 全部跟着改——§4 开头原话「牌局 UI 的全部开发可以先跳过加密层」现在是反事实,必须改,否则下一个前端会照它安排工期。
- **④ 数据模型正确性**:`DEV_USERS` 追加三项。**追加是安全的**:`_dev_uid(index)=index+1`,只追加不改序 ⇒ 既有行 uid 不变;已把「只可追加、改序会错配已有行」写进 `gameconfig` 的字段注释,免得后人图整齐去排序。
- **⑤ 规范合规**:新增配置项同步进 `poker.env.example`(本仓 `*.example` 是实际加载基线,不是模板);冒烟脚本里写死的账号名收成常量。
- **⑥ 测试充分**:退役本身有正面护栏(断言路由不存在)。**缺口如实记**:`Connection.channel is None` 这条分支现在只有测试在走,等于生产不可达代码;它换来的是 shell 接线测试的可读性,这个取舍已写进注释,但**没有任何机制防止它日后被误当成"还有明文入口"而被接线到某个新端点上**——真要防住得给 `Connection` 加断言或把明文帧抽成测试专用子类,本批未做。
- **⑦ 流程账本**:本篇即账本。三条用户定案(不做注册端点 / 可以关明文端点 / CI 那条我说重了)按 README §5 记进「用户定案」节,并落到对应设计文档,不留在对话里。
